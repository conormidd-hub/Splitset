# Splitset — Muscle Load & Recovery Model

Version 2.0 · 2026-10-16

Every logged set is scored against the user's monthly PB for that exercise, spread across up to seven muscles by role, turned into a recovery window, and shown on a front/back body figure on a six-step scale from clear through yellow to dark red. This document is the math. Every number in it is a constant in `data/recovery_constants.json`, and every worked example is a fixture in `data/load_model_fixtures.json`.

## 1. Pipeline

```
set (weight, reps, RPE?)          §3  effective weight, e1RM
  → reference PB for this set     §3  monthly PB, updated mid-session
  → set load (INOL)               §4  reps ÷ distance from max
  → exercise load                 §5  Σ set loads × fatigue factor
  → muscle load                   §6  Σ role weight × exercise load
  → recovery window               §7  hours, scales with muscle load
  → fatigue now                   §8  decaying terms that stack across workouts
  → level, colour, ready-in       §9  six steps, clear → dark red
```

§3–§7 run once when a workout is finished and are cached per workout per muscle. §8–§9 run every time the figure is drawn. Colours are never stored.

## 3. Strength reference: e1RM and the monthly PB

### 3.1 Estimated 1RM

```
RIR       = 10 − RPE (clamped 0..5) if RPE is logged, else 0
reps_used = min(reps + RIR, 20)
e1RM      = weight                              if reps_used ≤ 1
          = weight × (1 + reps_used / 30)       otherwise            (Epley)
```

- **RPE is optional.** When logged it makes the e1RM honest: 100 × 5 at RPE 8 is 123.3, not 116.7 (F04). Without it the set is assumed taken to failure, which gives the lowest e1RM and therefore the highest load: the safe side.
- **20-rep cap.** Epley drifts above 20 reps. A 25-rep set still scores; its e1RM is computed as if it were 20, which can only underestimate.

### 3.2 Effective weight by load mode

Each library exercise has a `load_mode`.

| Mode | Effective weight `w` | Example |
|---|---|---|
| `weight` | logged weight (per hand for dumbbells, as the library notes say) | bench 90 kg |
| `bodyweight` | bodyweight × `bw_factor` + added load | pull-up, 80 kg body + 10 kg belt → 90 (F08) |
| `assisted` | bodyweight × `bw_factor` − assistance | assisted pull-up, 80 kg body, 30 kg assist → 50 (F09) |
| `fixed` | none: no usable weight; scored per set (§4.3) | plank, dead bug, band pull-apart |

Bodyweight comes from the user profile (or the latest Garmin weigh-in); 75 kg if unknown. It is **snapshotted on the set when the set is saved**, so a later change of bodyweight never rescores old sets (F31).

### 3.3 What is stored

- Every set with an effective weight stores its `e1rm` at save time, using RIR from RPE or 0, plus the `bodyweight_kg` snapshot for bodyweight and assisted exercises. Warm-ups included: a warm-up never limits a PB, so counting it is harmless.
- `manual_pbs`: user-entered bests (weight × reps, a date), converted to e1RM the same way. A manual entry's time is the start of its date in the user's time zone, so it counts for any session that starts after that.
- The "monthly PB" and "all-time PB" are queries over those two sources, not stored columns.

### 3.4 Reference PB before a session

Resolved once per exercise at the session's start time. First rule that produces a number wins.

| # | Source | Rule | Worked example |
|---|---|---|---|
| 1 | **Monthly** | Max e1RM over this exercise's logged sets **and** manual entries dated in the 30 days before the session | Sets of 114 and 119 last fortnight, manual 120 entered last week → 120 |
| 2 | **Lapsed** | Nothing in 30 days but older records exist → best e1RM in the 30 days up to the most recent record, × 0.95 | Last benched 60 days ago, best that month 120 → 114 (F13) |
| 3 | **Estimated** | No records ever → follow `pb_estimate` links (up to 4 hops; library chains use at most 3, leaving one for a custom exercise) to the first lift that has rule 1 or 2; multiply the ratios, then × 0.90. If that anchor is itself lapsed, its 0.95 applies too | Incline DB press, bench PB 120 → 120 × 0.32 × 0.9 = 34.56 (F14). DB curl → BB curl → row → bench: 120 × 0.45 × 0.45 × 0.85 × 0.9 = 18.59 (F15). If BB curl has a PB of 45 it is used instead: 18.23 (F16) |
| 4 | **Calibration** | Nothing at all → no reference; the session's own sets set it (§3.5), assuming 2 reps in reserve when no RPE is logged | Landmine press 3 × 10 @ 30, no history → reference 42.0, I 0.714, exercise load 1.05 (F17) |

Rules 1 and 2 also report whether the winning record was logged or manual, so the UI can show the reference's source. The 0.90 on estimates and the 0.95 on lapsed PBs push errors one way: a PB that is too low makes every set look harder, which means more rest, never less.

### 3.5 Updating the reference inside a session

```
ref(set k) = max( PB_before, e1RM of every set 1..k of this exercise in this session )
```

A set that beats the reference raises it **before** it is scored. So no set can be scored as heavier than the user just proved they can lift. Bench, PB 120, 115 × 3 (e1RM 126.5) → ref 126.5 → I 0.909 (F02).

In a calibration session the e1RM used for `ref` adds the 2 assumed reps in reserve; the e1RM **stored** on the set does not (§3.3). The first session's sets are scored a little leniently. The stored PB stays conservative.

### 3.6 Manual PBs vs logged PBs

A manual entry is a dated record in the same monthly window as logged sets:

- **A logged set that beats it replaces it immediately.** The max rule does this; nothing else is needed. Manual 130 on day 0, logged 120 × 3 (132) on day 10 → reference 132 from then on (F18).
- **A lower logged set does not replace it.** The first sessions on a lift are often sub-maximal. If 3 × 10 at 60 kg (e1RM 80) replaced a genuine 120 kg best, every later set would score at roughly double its real load.
- **Manual entries expire with the window.** After 30 days a manual entry falls out of rule 1 like any other record, and logged data is in charge. Manual 130 never beaten, logged 100 × 5 sessions on days 1, 15 and 29 → reference on day 31 is 116.7 (F19).

That is the default policy, `pb.manual_policy = max`. The alternative, `replace_on_log`, retires a manual entry as soon as any logged set of that exercise is dated after it: the same timeline gives 130 on day 1, then 116.7 from day 3 (F29). Simpler to explain, but it lets a light first session undercut a real best.

## 4. Set load (INOL)

### 4.1 Formula

```
I    = min(w / ref, 0.95)                     relative intensity
INOL = min(reps, 20) / (100 × (1 − I))        Prilepin's intensity-number-of-lifts
```

INOL is reps divided by the distance from 100%, which puts heavy-low-rep and light-high-rep work on one scale. Because of §3.5, the hardest a set can ever score is a set taken to failure: `0.30 + reps/100`, so 0.35 for a 5-rep max, 0.40 for a 10-rep max, 0.50 for a 20-rep max. Singles are capped at 0.20 by the 0.95 intensity cap (F02).

### 4.2 Rep schemes compared (bench PB 120)

| Sets × reps @ kg | I | INOL per set | Exercise load |
|---|---|---|---|
| 3 × 10 @ 84 | 0.70 | 0.333 | 1.00 |
| 4 × 8 @ 90 | 0.75 | 0.320 | 1.28 |
| 5 × 5 @ 102 | 0.85 | 0.333 | 1.67 |
| 8 × 3 @ 108 | 0.90 | 0.300 | 2.40 |
| 3 × 15 @ 72 | 0.60 | 0.375 | 1.13 |
| 10 × 10 @ 72 | 0.60 | 0.250 | 2.50 |

A working set costs about 0.3 whatever the rep scheme. The total is driven by how many hard sets and how close to the PB they were. Per exercise per session, Prilepin's rough bands: under 0.4 barely counts; 0.4–1.0 productive; 1.0–2.0 hard; over 2.0 very hard.

**Flexibility between sets.** Every set is scored on its own weight, reps and reference, so pyramids, back-off sets and drop sets need no special handling. A bench pyramid with PB 120 (F05):

| Set | ref | I | INOL |
|---|---|---|---|
| 60 × 12 (warm-up) | 120 | — | excluded |
| 80 × 8 | 120 | 0.667 | 0.240 |
| 100 × 5 | 120 | 0.833 | 0.300 |
| 110 × 3 (e1RM 121, new PB) | 121 | 0.909 | 0.330 |
| 90 × 8 back-off | 121 | 0.744 | 0.312 |
| **Exercise load** | | | **1.182** |

### 4.3 Fixed-cost sets

For `load_mode = fixed` there is no weight to compare with a PB. Each working set costs one typical hard set, adjusted by RPE if logged:

```
cost = 0.30                                              no RPE
cost = clamp(0.30 + 0.05 × (RPE − 8), 0.10, 0.40)        with RPE
```

Plank 3 × 60 s → 0.90 (F10); at RPE 9 → 1.05 (F11). Duration is recorded but does not change the cost. A 90 s hold for one person is a 30 s hold for another, and without a timed PB the app cannot tell which.

### 4.4 Warm-ups and unilateral sets

- **Warm-ups** (`is_warmup`) contribute no load but do feed e1RM and the reference (F07).
- **Unilateral exercises.** One logged set covers both sides. If the logger records sides as separate sets (`side = left | right`), each counts 0.5 (F12), so the total is the same either way.

## 5. Exercise load

```
L_e = fatigue_factor_e × Σ INOL (or fixed cost) over the working sets of e in the workout
```

| Fatigue class | Factor | Which exercises |
|---|---|---|
| `high` | 1.2 | Heavy free-weight compounds and big-stretch eccentrics: barbell squat and deadlift variants, barbell and dumbbell RDLs, stiff-leg deadlifts, good mornings, lunges and split squats, Nordic curls, glute-ham raises, power cleans, sled pushes |
| `standard` | 1.0 | Free-weight presses, rows, pull-ups, dumbbell work, heavy machine compounds (leg press, hack squat) |
| `low` | 0.8 | Machines, cables and bands; calf raises; light bodyweight core |

The class is per exercise in the library. Same INOL on a cable pushdown and on a heavy deadlift does not cost the same recovery. This factor is the only place that difference enters.

---

## 6. Muscle load

```
L_m,w = Σ over exercises e in workout w of role_weight(e, m) × L_e
```

| Role | Weight | Meaning | Cap per exercise |
|---|---|---|---|
| primary | 1.0 | the muscle the exercise is for; limits the set | 2 |
| secondary | 0.4 | does real work, does not limit the set | 2 |
| tertiary | 0.2 | stabilises or assists; fatigues, is not trained | 3 |

**Load split** (for the exercise picker): `split_m = role_weight_m / Σ role_weights`, rounded to sum to 100. Bench press: chest 56 · triceps 22 · front delts 22.

### 6.1 Worked push day

PBs: bench 120, incline DB 40, DB shoulder press 30, lateral raise 13, rope pushdown 40, skullcrusher 40.

| Exercise | Sets | ref | I | Per set | Factor | L_e |
|---|---|---|---|---|---|---|
| Bench press (barbell) | 4 × 8 @ 90 | 120 | 0.750 | 0.320 | 1.0 | **1.280** |
| Incline bench press (dumbbell) | 3 × 10 @ 30 | 40 | 0.750 | 0.400 | 1.0 | **1.200** |
| Shoulder press (dumbbell) | 3 × 8 @ 22.5 | 30 | 0.750 | 0.320 | 1.0 | **0.960** |
| Lateral raise (dumbbell) | 3 × 15 @ 10 | **15** | 0.667 | 0.450 | 1.0 | **1.350** |
| Triceps pushdown (rope) | 3 × 12 @ 30 | **42** | 0.714 | 0.420 | 0.8 | **1.008** |
| Skullcrusher (EZ bar) | 3 × 10 @ 30 | 40 | 0.750 | 0.400 | 1.0 | **1.200** |

The lateral raise (10 × 15 → e1RM 15) and the pushdown (30 × 12 → 42) beat their stored PBs on the first set, so §3.5 raises the reference before scoring.

| Muscle | Contributions | L_m | Level |
|---|---|---|---|
| chest | 1.0 × 1.28 + 1.0 × 1.20 | **2.480** | High |
| triceps | 0.4 × 1.28 + 0.4 × 1.20 + 0.4 × 0.96 + 1.0 × 1.008 + 1.0 × 1.20 | **3.584** | Very high |
| front_delts | 0.4 × 1.28 + 0.4 × 1.20 + 1.0 × 0.96 | **1.952** | High |
| side_delts | 0.4 × 0.96 + 1.0 × 1.35 | **1.734** | High |
| traps | 0.2 × 0.96 + 0.2 × 1.35 | **0.462** | Low |

Every other muscle is 0 (F20).

## 7. Recovery window

```
R_m,w = base_hours_m × clamp(0.5 + 0.3 × L_m,w, 0.5, 2.0)
```

Each extra set adds a little recovery time; there are no steps where one set adds a day. For a 48 h muscle:

| L_m | Multiplier | R (h) | Trainable after (h) | Ready after (h) |
|---|---|---|---|---|
| 0.5 | 0.65 | 31.2 | 0 | 15.6 |
| 1.0 | 0.80 | 38.4 | 0 | 28.8 |
| 2.5 | 1.25 | 60.0 | 24.0 | 54.0 |
| 4.0 | 1.70 | 81.6 | 51.0 | 76.5 |
| ≥ 5.0 | 2.00 | 96.0 | 67.2 at L = 5 | 91.2 at L = 5 |

For a single workout on its own:

```
trainable after = R × (1 − 1.5 / L)     if L > 1.5, else 0
ready after     = R × (1 − 0.25 / L)    if L > 0.25, else 0
```

These two numbers are the **recovery days** shown per muscle on the workout summary. Push day: chest R 59.7 h, trainable after 23.6 h, ready after 53.7 h (2.2 days); triceps R 75.6 h, trainable after 44.0 h, ready after 70.3 h (2.9 days); side delts ready after 21.0 h (F20).

## 8. Fatigue over time

Each workout leaves a term per muscle that decays linearly to zero over its window:

```
F_m(t) = Σ over workouts w with t_w ≤ t of   L_m,w × max(0, 1 − (t − t_w) / R_m,w)
```

`t_w` is the workout's finish time. Only workouts within the longest possible window can be non-zero: max base hours × 2.0, which is 144 h with the defaults. The engine derives this from the constants, so raising base hours in settings never cuts a term off early.

**Stacking falls out of the sum.** Chest after the push day: 2.48 → 1.98 at 12 h → 1.48 at 24 h → 0.98 at 36 h → 0.49 at 48 h → 0.24 at 54 h (F23). Repeat the push day at 24 h and chest is 1.48 + 2.48 = 3.96, Very high; triceps 6.03, Extreme (F24).

**Weekly guard.** Slow overreach can hide between decaying terms, so:

```
W_m(t) = Σ L_m,w over workouts with 0 ≤ t − t_w < 168 h
if W_m ≥ 8.0, the displayed level is at least 4 (Very high)
```

Chest pushed at 0, 48, 96 and 144 h: at 150 h F is 2.47 (High) but W is 9.92, so it shows Very high; at 168.25 h the first session leaves the week, W drops to 7.44 and chest shows Moderate (F 1.47) (F25). A normal push/pull/legs week run twice peaks at W 7.17 (triceps), so the guard only trips on genuinely high frequency (F27).

## 9. Levels and colours

One scale for everything: current fatigue on the recovery view, a workout's own load on the session view.

| Level | F (or L) | Label | Light fill | Dark fill | Advice |
|---|---|---|---|---|---|
| 0 | < 0.25 | Ready | `#D9DDE3` (neutral) | `#3A3F47` | Good to train |
| 1 | 0.25 – 0.75 | Low | `#FFE58A` | `#FFE58A` | Good to train |
| 2 | 0.75 – 1.5 | Moderate | `#FDBA4D` | `#FDBA4D` | Can train; expect slightly lower performance |
| 3 | 1.5 – 2.5 | High | `#F77B30` | `#F77B30` | Rest, or train it lightly |
| 4 | 2.5 – 4.0 | Very high | `#DE3A24` | `#E5432C` | Rest |
| 5 | ≥ 4.0 | Extreme | `#9C0E25` | `#C0182F` | Rest; well past a normal session |

Lower bounds are inclusive. Levels 1 to 5 fall steadily in lightness (OKLab L 0.92 → 0.44), so their order survives colour-blindness. Ready is told apart by being neutral grey, not by lightness: in light mode it sits close to Low (contrast 1.1 : 1), and in dark mode it is darker than every level. So the figure always has a text equivalent (§10).

How the scale lands in practice: a typical primary-muscle session of 6–8 hard sets gives L ≈ 2–3, High to Very high straight after. It is trainable again in about a day and fully ready in two to three. A single isolation set gives L ≈ 0.4: Low, ready in about half a day (F21).

**Trainable and ready.**

```
trainable_at = first t ≥ now where displayed level ≤ 2
ready_at     = first t ≥ now where displayed level = 0
```

Without a new workout F only falls, and W only drops when a workout passes 168 h. Scan at 15-minute steps up to the longest window plus 168 h, or solve the piecewise-linear segments exactly. Display: `now` if ≤ 0; `N h` under 24 h; otherwise `N.N days`.

## 10. Views

| View | Colours by | Where |
|---|---|---|
| **Recovery view** | current `F_m(now)`, with the weekly guard | Recovery screen / home card (default) |
| **Session view** | this workout's `L_m,w` | Workout summary, after Finish |
| **List view** | same numbers as text | Toggle under the figure; required, since colour alone cannot carry the meaning |

**Tap detail** for a region: muscle name, level label and advice, F (or L), trainable-in and ready-in, weekly load W, and the contributing exercises from the last 168 h: exercise, date, role badge (P/S/T), and `role_weight × L_e`, largest first. Estimated or calibration-based references carry a small "estimated" or "calibrating" marker, because early colours on that muscle are provisional.

**Figure contract.** Each region in the SVG is a `<path>` with `data-muscle` set to a muscle ID and `data-side` (viewer's left/right). A muscle may have several paths, on one or both views; all paths for a muscle take the same fill. Silhouette shapes carry `data-role="silhouette"` and never take a level colour; they switch between `silhouette_fill` and `silhouette_fill_dark` with the theme, and region strokes between `region_stroke` and `region_stroke_dark`. Element ids are prefixed `front-` / `back-` so both views can sit on one page.

## 11. Stored vs computed

| Stored | Computed |
|---|---|
| `sets`: exercise, weight, reps, rpe?, seconds?, side?, is_warmup, completed_at, **e1rm** and **bodyweight_kg** (at save) | ref, I, INOL per set |
| `manual_pbs`: exercise, weight, reps, e1rm, dated_at | monthly / lapsed / estimated / calibration reference |
| `exercise_muscles`: exercise, muscle, role | L_e, L_m, R per workout (cached below) |
| `muscles`: id, group, base_hours | F, W, level, colour, trainable/ready times |
| `workout_muscle_loads`: workout, muscle, L_m, R, t_w, source | |
| `user_thresholds`: per-user overrides of any constant | |

`workout_muscle_loads` is written when a workout is finished and rewritten by the recompute rule in §14. It is derivable, but caching it makes the figure a query over at most a week of rows instead of a re-score of every set, and it makes history (the map as of any past date) cheap.

## 12. Constants

All in `data/recovery_constants.json`, overridable per user. The ones that most change behaviour:

| Constant | Default | Effect of raising it |
|---|---|---|
| `role_weights.secondary` / `.tertiary` | 0.4 / 0.2 | Indirect work counts for more |
| `fatigue_factors.high` / `.low` | 1.2 / 0.8 | Raising `high` or lowering `low` widens the gap between barbell compounds and machines |
| `pb.window_days` | 30 | PB reacts more slowly to detraining |
| `pb.manual_policy` | `max` | `replace_on_log` retires manual bests at the next logged set (§3.6) |
| `recovery.slope` | 0.3 | Heavy sessions get much longer windows |
| `base_recovery_hours.default` | 48 | Every muscle recovers more slowly |
| `fatigue.weekly_cap` | 8.0 | Weekly guard trips less often |
| `levels[*].min` | 0.25 / 0.75 / 1.5 / 2.5 / 4.0 | Figure looks cooler for the same load |

## 14. Edge cases

- No sets in the last 168 h → every muscle Ready.
- A workout in progress → score completed sets with `t_w = now`; the figure updates live.
- An exercise with no muscle mapping → contributes nothing, never throws (F22).
- A set with zero or negative effective weight (assistance ≥ body) → skipped.
- The same exercise logged in two blocks of one workout → one running reference across both blocks (F28).
- Bodyweight changes → only new sets use the new value; old sets keep their snapshot.
- Editing or deleting a finished workout, an exercise's mapping or fatigue class, or a manual PB → recompute `workout_muscle_loads` for **every** finished workout from the earliest affected one onward, in time order. Not just the same exercise: estimated references cross exercises (a curl's reference can come from bench).
- Clock: all times in UTC on the server; display in the user's time zone.

## 15. Known limits

The model ranks and times recovery well enough to guide a training split. It is not a physiological measurement. Epley is approximate, especially for high reps and singles. Linear decay simplifies a curve that in reality depends on sleep, nutrition and training age. Estimated PB ratios are population rough-cuts that the first logged session replaces. Fixed-cost sets ignore duration. Every one of these is a constant or a single function, so it can be tuned against the user's own history (build phase 11).
